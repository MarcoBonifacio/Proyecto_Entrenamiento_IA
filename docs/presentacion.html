Contexto & Justificación

El Problema y la Solución Tecnológica

Automatizando el reconocimiento en origen para evitar la contaminación cruzada

❌ El Problema Actual

• Dificultad de reconocimiento: Los ciudadanos y operarios dudan sobre el material exacto de un residuo (ej. envases multicapa, tipos de plásticos o metales).

• Contaminación cruzada: Si un residuo no reciclable o sucio se arroja en un contenedor de reciclaje limpio, inutiliza todo el lote.

• Pérdida económica y ambiental: Solo una fracción mínima de materiales se recicla efectivamente debido a la mala segregación en origen.

✅ La Solución: EcoClasifica

• Reconocimiento por Imagen: El usuario fotografía el residuo y el sistema predice la categoría exacta en tiempo real.

• Porcentaje de Confianza: Proporciona la certidumbre probabilística calculada por la red neuronal profunda.

• Educación y Guía Inmediata: Entrega recomendaciones claras: en qué color de contenedor depositarlo y cómo prepararlo (lavar, aplanar, secar).

Machine Learning & Deep Learning

Arquitectura del Modelo de IA (ResNet-50)

Transfer Learning sobre redes convolucionales residuales profundas

🧠 Modelo Base

microsoft/resnet-50

Red convolucional de 50 capas preentrenada sobre ImageNet-1k (más de 1 millón de imágenes). Sus conexiones residuales (skip connections) evitan el desvanecimiento del gradiente.

🔄 Transfer Learning

Aprovechamiento de Features

Reutilizamos los filtros visuales profundos ya aprendidos (texturas, bordes y reflejos de materiales) y reemplazamos la cabeza clasificadora final para adaptarla a nuestras 6 clases.

⚙️ Pipeline de Inferencia

Entrada 224 × 224 RGB

El AutoImageProcessor normaliza los píxeles. La red produce *logits* que se transforman mediante la función Softmax en probabilidades reales porcentuales.

📐 Fórmula Matemática de Salida (Softmax)
P(Clase_i) = exp(logit_i) / Σ exp(logit_j)   ⟶   Garantiza que la suma de probabilidades de las 6 categorías sea exactamente 100%.
🗣️ Guion de Presentación — Qué decir en esta diapositiva:
"Para el modelo elegimos ResNet-50 con Transfer Learning. En lugar de entrenar una red desde cero, aprovechamos el conocimiento visual previo de millones de imágenes y reentrenamos la última capa densa hacia 6 clases de residuos. La inferencia redimensiona la imagen a 224 por 224 píxeles y calcula la distribución de probabilidad completa mediante la función Softmax."
Datos & Segregación Ecológica

Dataset TrashBusters y las 6 Categorías

29,849 registros etiquetados bajo la norma estándar de contenedores de reciclaje

📦 Cartón (`cardboard`)
Contenedor Azul

Cajas, empaques y corrugados. Recomendación: aplanar, retirar cintas y grapas, depositar seco y sin grasa.

🫙 Vidrio (`glass`)
Contenedor Verde

Botellas, frascos y tarros. Recomendación: retirar tapas metálicas o plásticas, enjuagar residuos orgánicos.

🥫 Metal (`metal`)
Contenedor Amarillo

Latas de conserva, gaseosa, aluminio. Recomendación: escurrir, aplastar latas de bebidas para ahorrar volumen.

📄 Papel (`paper`)
Contenedor Azul

Hojas, periódicos, revistas limpias. Recomendación: no arrugar innecesariamente, evitar papel con carbón o mojado.

♻️ Plástico (`plastic`)
Contenedor Amarillo

Botellas PET, tapas, envases PEAD. Recomendación: compactar, colocar la tapa para facilitar el reciclaje.

🗑️ Basura General (`trash`)
Contenedor Gris / Negro

Residuos no reciclables o contaminados. Recomendación: envolver bien para relleno sanitario seguro.

Clean Code & Calidad de Código

Refactorización: Eliminación de Code Smells

Solución al reporte de constantes no detectadas y magic numbers

Code Smell 1: Magic Numbers

Problema: Valores como 128, 0.8 y 2 estaban hardcodeados dentro del cuerpo de las funciones.

# ❌ ANTES (Magic Numbers) if max_dimension < 128: confidence *= 0.8 return round(confidence, 2)
Refactorización: Extract Constant

Solución: Constantes explícitas UPPER_CASE tipadas en la cabecera del módulo.

# ✅ DESPUÉS (Constantes UPPER_CASE) LOW_RESOLUTION_THRESHOLD: int = 128 CONFIDENCE_ADJUSTMENT: float = 0.8 ROUND_DECIMALS: int = 2 if max_dimension < LOW_RESOLUTION_THRESHOLD: confidence *= CONFIDENCE_ADJUSTMENT return round(confidence, ROUND_DECIMALS)
Code Smell 2: Dead Code (Constantes Huérfanas)

Anteriormente se habían pegado bloques de constantes al final de los archivos que nunca eran invocadas por las funciones. La IA del profesor las detectó como inexistentes en el flujo lógico.

Solución: Reubicación & Uso Activo

Se eliminó el código muerto del pie de página y se reubicaron en la cabecera según el estándar PEP8, conectándolas con los argumentos reales (ej. DEFAULT_SERVER_PORT = 7860).

🗣️ Guion de Presentación — Qué decir en esta diapositiva:
"Un punto crítico solicitado por el profesor fue corregir la falta de constantes definidas. Identificamos el code smell de Magic Numbers y Código Muerto: habían números sueltos dentro de las funciones y constantes huérfanas al final del archivo. Aplicamos la técnica de refactorización Extract Constant, definiendo identificadores UPPER_CASE tipados a nivel de módulo y eliminando cualquier valor literal sin nombre."

🧪 ¿Qué verifican los Tests Agregados?

1. Valores y Tipos de Constantes: Aserta formalmente que las constantes globales existen con tipos estrictos (str, float, int).

2. Resiliencia ante Nulos: Prueba que normalize_material_name(None) retorna de forma segura DEFAULT_CATEGORY.

3. Pruebas de Frontera (Boundary Testing): Comprueba la degradación exacta de confianza en el límite de 128 píxeles.

4. Postprocesamiento Robusto: Prueba listas de probabilidades y descarte de elementos malformados.

DevOps & Automatización

Pipeline CI/CD en GitHub Actions

Automatización continua multi-entorno con Quality Gates estrictos

⚡ Disparadores & Matriz de Entorno

• Triggers: Se activa en cada push a ramas main y develop, y en cada pull_request hacia main.

• Runner: Contenedores virtuales con ubuntu-latest.

• Matrix Multi-versión: Trabajos concurrentes en Python 3.10 y Python 3.11 para asegurar compatibilidad.

🛡️ Quality Gates de Protección

• Cobertura Obligatoria: coverage report --fail-under=60 detiene el flujo si la cobertura cae por debajo del 60%.

• Linter Estricto: flake8 src/ --max-line-length=120 rechaza código con problemas de estilo PEP8 o errores sintácticos.

1
Checkout: Clona el repositorio con actions/checkout@v4.
2
Setup Python: Configura la versión correspondiente con actions/setup-python@v5.
3
Install: Actualiza pip e instala dependencias de requirements.txt, coverage y flake8.
4
Tests & Coverage: Ejecuta batería de pruebas unitarias y genera reporte de cobertura.
5
Linting: Audita el código con flake8 para garantizar calidad y legibilidad.
🗣️ Guion de Presentación — Qué decir en esta diapositiva:
"Como responsable de DevOps y CI/CD, configuré el pipeline en GitHub Actions ubicado en .github/workflows/ci.yml. En cada push o pull request se levantan entornos limpios en Ubuntu con Python 3.10 y 3.11. El pipeline ejecuta los tests, verifica que la cobertura supere el 60% y audita el estilo con flake8. Si cualquiera de estos pasos falla, el merge queda bloqueado."
