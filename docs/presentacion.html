● Problemática Identificada

La separación errónea de desechos sólidos en origen por desconocimiento ciudadano genera contaminación cruzada en contenedores de reciclaje, reduciendo el aprovechamiento en instituciones educativas, municipios y plantas de reciclaje.

● Objetivo del Sistema

Clasificar automáticamente fotografías de residuos en 6 categorías mediante una red profunda Microsoft ResNet-50 afinada, servida por una API REST FastAPI y una SPA React dentro de un contenedor Docker portable.

● Público Objetivo

Estudiantes y docentes universitarios, hogares, puntos limpios municipales, plantas de segregación y programas de educación ambiental que requieren clasificación asistida en tiempo real.

● Stack Tecnológico Principal

Python 3.11 FastAPI Uvicorn PyTorch >=2.0 Transformers ResNet-50 React 19.3 Tailwind v4 Docker Compose

💻 Normalización Defensiva de Probabilidades en classifyApi.ts
frontend/src/features/classification/api/classifyApi.ts
const toProbability = (value: unknown): number => {
  const n = typeof value === 'number' ? value : Number(value);
  if (!Number.isFinite(n) || n < 0) return 0;
  return n > 1 ? Math.min(n / 100, 1) : n;
};

export const normalizeClassification = (raw: ClassifyApiResponse): ClassificationResponse => {
  const breakdown = Object.entries(raw.todas_las_predicciones ?? {})
    .map(([label, p]) => ({ label, percent: toProbability(p) * 100 }))
    .sort((a, b) => b.percent - a.percent);
  return {
    prediction: raw.categoria?.trim() || 'Desconocido',
    confidence: toProbability(raw.confianza),
    emoji: raw.emoji ?? '',
    disposal_recommendation: raw.recomendacion || undefined,
    breakdown,
  };
};

Análisis Técnico del Checkpoint Afinado y Limitaciones Reales del Modelo

Comportamiento de logits en classifier.1.weight, métricas de evaluación y mejoras para iteraciones futuras

Accuracy: 58.42% · F1 Macro: 0.4709
🔬 Diagnóstico Real: Dispersión/Compresión de Logits en classifier.1.weight
Limitación Técnica Clave

Al inspeccionar los tensores de models/ecoclasifica-resnet50/model.safetensors (94.3 MB) entrenados en CPU durante 5 épocas (learning_rate: 5e-5, batch_size: 16, weight_decay: 0.01):

1. Magnitud acotada en classifier.1.weight: Los pesos de la nueva cabeza lineal (shape [6, 2048]) partieron de inicialización aleatoria mientras el backbone preentrenado tenía gradientes suaves con lr=5e-5. Tras solo 5 épocas en CPU, los logits resultantes (z_i) presentan valores cercanos entre sí.
2. Efecto en Softmax: Cuando la diferencia entre logits es pequeña, la exponencial exp(z_i) / Σ exp(z_j) produce confianzas repartidas (por ejemplo 30%–45% en la clase principal y 15%–20% en clases secundarias) especialmente ante tomas ambiguas, ángulos inusuales o fondos ruidosos.
3. Corrección crítica aplicada en src/preprocess.py: Se eliminó el doble img.resize((224,224)) previo y se cargó el preprocessor_config.json local con @lru_cache para que la inferencia use exactamente el mismo recorte central del entrenamiento.

⚠️ Las 5 Limitaciones Actuales y Hoja de Ruta de Mejora
Transparencia Científica
Limitación IdentificadaCausa RaízSolución en Próxima Iteración
1. Compresión de logits y confianzas repartidas Solo 5 épocas en CPU con lr=5e-5 sobre classifier.1.weight. Entrenar 15–25 épocas en GPU, usar two-stage fine-tuning (congelar backbone 3 épocas con lr=1e-3 en cabeza).
2. Sensibilidad a fondos ruidosos o múltiples objetos Dataset TrashNet (2,527 fotos) tiene fondos blancos/limpios y 1 objeto por foto. Aplicar Data Augmentation agresivo (RandomBackground, ColorJitter) y ampliar con TrashBusters.
3. Clasifica material visual, no estado higiénico No distingue si una caja de cartón tiene grasa o restos orgánicos. Añadir sub-etiquetas de contaminación o advertencia preventiva en la UI.
4. Clase trash heterogénea Agrupa residuos no reciclables de geometrías muy distintas. Subdividir en orgánicos, textiles y multicapa.
5. Sin umbral de rechazo duro Softmax siempre suma 100% entre las 6 clases. Activar rechazo cuando confianza < CONFIDENCE_THRESHOLD (0.60).

Al entrenar 5 épocas en CPU con learning_rate=5e-5, los pesos de la capa final classifier.1.weight producen logits cercanos entre sí; al pasar por Softmax, esto genera probabilidades repartidas si la foto tiene fondo ruidoso o iluminación deficiente. 🐳 Código Completo del Dockerfile en la Raíz del Proyecto
Dockerfile
FROM python:3.11-slim

ENV PYTHONDONTWRITEBYTECODE=1 \
    PYTHONUNBUFFERED=1 \
    ECOCLASIFICA_MODEL_PATH=/app/models/ecoclasifica-resnet50 \
    ECOCLASIFICA_FRONTEND_DIST=/app/frontend/dist

# Dependencias de sistema (OpenCV/Pillow/torchvision)
RUN apt-get update \
    && apt-get install -y --no-install-recommends libgl1 libglib2.0-0 \
    && rm -rf /var/lib/apt/lists/*

WORKDIR /app

# Dependencias Python (capa cacheable)
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# Código fuente + Build React + Modelo ResNet-50 afinado
COPY src/ ./src/
COPY frontend/dist/ ./frontend/dist/
COPY models/ecoclasifica-resnet50/ ./models/ecoclasifica-resnet50/

EXPOSE 8000
CMD ["uvicorn", "src.fastapi_app:app", "--host", "0.0.0.0", "--port", "8000"]
🔍 Decisiones de Arquitectura en el Dockerfile

1. Base python:3.11-slim: Reduce drásticamente el peso del sistema operativo base e instala únicamente libgl1 y libglib2.0-0 requeridas por Pillow/Torchvision.
2. Variables de Entorno sin Rutas Hardcodeadas: Inyecta ECOCLASIFICA_MODEL_PATH y ECOCLASIFICA_FRONTEND_DIST para que FastAPI localice tanto el modelo como el frontend dentro de /app.
3. Orden Estratégico de Capas: COPY requirements.txt va antes de COPY src/; así Docker reutiliza la capa de PyTorch en caché si solo cambia el código.
4. Optimización con .dockerignore: Excluye .git/, venv/, frontend/node_modules/, data/, *.zip (223 MB) y copias duplicadas de pesos en la raíz.
